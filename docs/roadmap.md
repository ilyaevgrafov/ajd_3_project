# План реализации функциональности

Этот документ перечисляет **согласованные функции в предполагаемой последовательности разработки**. Полные бизнес-правила и ограничения приведены в [requirements.md](requirements.md). Номера этапов задают порядок, но не сроки выполнения.

## Этап 1. Базовая аутентификация

- [ ] Регистрация пользователя: имя пользователя, отображаемое имя, почта, пароль.
- [ ] Проверка уникальности имени пользователя и почты.
- [ ] Вход по паролю.
- [ ] Выход из учётной записи.
- [ ] Ограничение доступа к защищённым операциям для неавторизованных пользователей.

**Результат:** пользователь может создать учётную запись и войти в систему.

## Этап 2. Базовый профиль

- [ ] Просмотр профиля.
- [ ] Изменение отображаемого имени.
- [ ] Изменение имени пользователя с проверкой уникальности.

**Результат:** пользователь может управлять основными публичными данными профиля.

## Этап 3. Базовые пространства и роли

- [ ] Создание пространства по названию.
- [ ] Автоматическое назначение роли `OWNER` создателю.
- [ ] Автоматическое создание начального и конечного статусов.
- [ ] Просмотр списка пространств пользователя.
- [ ] Поиск собственных пространств по названию.
- [ ] Базовый просмотр пространства в виде бэклога.
- [ ] Ролевая модель `GUEST` / `MEMBER` / `OWNER` и проверки прав чтения/изменения.

**Результат:** пользователь может создать пространство и открыть его, а система различает роли.

## Этап 4. Настраиваемые статусы и теги

- [ ] Создание промежуточных статусов.
- [ ] Переименование всех статусов.
- [ ] Изменение порядка промежуточных статусов.
- [ ] Запрет удаления и перемещения начального и конечного статусов.
- [ ] Удаление промежуточного статуса с переносом задач в начальный и предупреждением о числе затронутых задач.
- [ ] Создание, переименование и удаление тегов.
- [ ] Предупреждение о числе задач, которые потеряют удаляемый тег.

**Результат:** владелец настраивает рабочий процесс и набор тегов пространства.

## Этап 5. Создание и базовая работа с задачами

- [ ] Создание задачи с названием, описанием, необязательным дедлайном, приоритетом, статусом, тегами и признаком `assigneeCanEdit` (по умолчанию `false`).
- [ ] Фиксация пространства и создателя задачи.
- [ ] Возможность создать задачу для себя либо без исполнителя; владельцу — назначить любого `MEMBER` / `OWNER`.
- [ ] Отображение всех полей задачи.
- [ ] Редактирование и удаление создателем своей задачи.
- [ ] Полный контроль владельца пространства над задачами.
- [ ] Подтверждение удаления без архива или корзины.
- [ ] Поиск задач по названию и описанию.
- [ ] Сортировка по дедлайну и статусу.
- [ ] Фильтрация по исполнителю, тегам, дедлайну (сегодня, неделя, диапазон).

**Результат:** можно вести полноценный список задач пространства.

## Этап 6. Исполнители и редактирование содержимого

- [ ] Прямое назначение и смена исполнителя владельцем пространства.
- [ ] Запрет назначения гостя и пользователей вне пространства.
- [ ] Самостоятельное взятие `MEMBER` любой свободной задачи.
- [ ] Возможность освободить самостоятельно взятую задачу.
- [ ] Запрет самостоятельно отказаться от назначения владельцем.
- [ ] Учет источника назначения: нет назначения / прямое / самостоятельное.
- [ ] Защита от одновременного взятия одной задачи двумя пользователями.
- [ ] Изменение исполнителем статуса своей задачи.
- [ ] Изменение любым участником статуса свободной задачи.
- [ ] Флаг «Разрешить исполнителю редактировать задачу», по умолчанию выключен.
- [ ] Изменение флага только создателем задачи или владельцем пространства.
- [ ] Редактирование содержимого исполнителем при `assigneeCanEdit = true` независимо от способа назначения.
- [ ] Сохранение прав создателя собственной задачи независимо от способа назначения.

**Результат:** задачи распределяются между участниками с согласованными правилами изменения статуса и содержимого.

## Этап 7. Канбан

- [ ] Канбан пространства со столбцами в порядке пользовательских статусов.
- [ ] Начальный статус слева, конечный — справа.
- [ ] Отображение задач в соответствующих статусам столбцах.
- [ ] Изменение статуса через интерфейс канбана с соблюдением прав.

**Результат:** задачи можно отслеживать на доске по стадиям выполнения.

## Этап 8. Приглашения и управление участниками

- [ ] Приглашение зарегистрированного пользователя по имени пользователя.
- [ ] Выбор роли `GUEST`, `MEMBER` или `OWNER` при приглашении.
- [ ] Принятие и отклонение приглашения.
- [ ] Отмена ожидающего приглашения владельцем.
- [ ] Просмотр пользователей пространства и их ролей.
- [ ] Изменение роли уже вступившего пользователя.
- [ ] Исключение гостя или обычного участника.
- [ ] Снятие исполнителя при понижении до `GUEST` или прекращении участия.
- [ ] Предупреждение о затронутых назначениях.

**Результат:** пространство поддерживает совместную работу зарегистрированных пользователей.

## Этап 9. Выход, передача владения и удаление пространства

- [ ] Добровольный выход из пространства.
- [ ] Проверка, остаются ли владельцы после выхода.
- [ ] При выходе последнего владельца — выбор нового владельца из `MEMBER` либо удаление пространства.
- [ ] Автоматическое удаление пространства, если не остаётся ни `OWNER`, ни `MEMBER`.
- [ ] Запрет понизить последнего владельца без другого владельца.
- [ ] Сохранение созданных вышедшими или исключёнными пользователями задач.
- [ ] Снятие назначений вышедших или исключённых пользователей.
- [ ] Редактирование названия пространства владельцем.
- [ ] Удаление пространства с подтверждением и удалением зависимых данных.

**Результат:** корректно обрабатывается жизненный цикл пространства и его участников.

## Этап 10. История изменений задач

- [ ] Сохранение изменений полей задачи с указанием даты, автора и содержания изменения.
- [ ] Просмотр истории в интерфейсе задачи.
- [ ] Доступ к истории для всех пользователей пространства, включая гостей.
- [ ] Корректное отображение истории, если автор больше не состоит в пространстве или удалил аккаунт.

**Результат:** можно узнать, когда, кем и как изменялась задача.

## Этап 11. Календарь пространства

- [ ] Отображение задач пространства в календаре по дедлайнам.
- [ ] Просмотр задач из календаря.
- [ ] Соблюдение существующих прав на изменение задачи.

**Результат:** задачи с дедлайнами доступны в календарном представлении.

## Этап 12. Общие представления всех пространств

- [ ] Общий бэклог задач из всех пространств пользователя.
- [ ] Общий календарь задач из всех пространств пользователя.
- [ ] Общий канбан с двумя столбцами: «Не выполнено» и «Выполнено».
- [ ] Отнесение к выполненным только задач, находящихся в конечном статусе исходного пространства.
- [ ] Сохранение прав доступа и изменения из исходного пространства.

**Результат:** пользователь может видеть задачи из нескольких пространств в одном интерфейсе.

## Этап 13. Почта и восстановление доступа

- [ ] Отправка подтверждения почты после регистрации.
- [ ] Подтверждение адреса одноразовым кодом.
- [ ] Повторная отправка подтверждения.
- [ ] Восстановление пароля через зарегистрированную почту.
- [ ] Установка нового пароля после успешного подтверждения.

**Результат:** реализованы подтверждение почты и восстановление доступа.

## Этап 14. Безопасность и удаление учётной записи

- [ ] Изменение пароля с проверкой текущего и подтверждением одноразовым кодом по электронной почте.
- [ ] Изменение почты с проверкой пароля и подтверждением нового адреса.
- [ ] Удаление аккаунта с проверкой пароля и предупреждением.
- [ ] Автоматический выход из всех пространств при удалении аккаунта.
- [ ] Автоматическая передача владения первому по времени вступления оставшемуся `MEMBER`, а при отсутствии `MEMBER` — первому `GUEST`, если других владельцев нет; разрешение совпадений по `user_id`.
- [ ] Удаление пространства, если после удаления аккаунта в нём не остаётся пользователей.
- [ ] Сохранение задач и истории в пространствах, которые продолжают существовать; снятие назначений удалённого пользователя.

**Результат:** пользователь может безопасно изменять учётные данные и удалять учётную запись.

## Этап 15. Аватар пользователя

- [ ] Загрузка аватара.
- [ ] Замена аватара.
- [ ] Удаление аватара.

**Результат:** пользователь может управлять изображением профиля.

## Этап 16. Аналитика пространства

- [ ] Общий показатель количества задач.
- [ ] Общий показатель количества просроченных задач.
- [ ] Текущее распределение задач по статусам.
- [ ] Индивидуальное количество задач, назначенных участнику.
- [ ] Индивидуальное количество просроченных задач участника.
- [ ] Текущее распределение задач участника по статусам.
- [ ] Выбор периода для применимых показателей: текущий день, текущая неделя, выбранный промежуток, всё время.
- [ ] Общая аналитика доступна всем пользователям пространства, включая гостей.
- [ ] Индивидуальная аналитика доступна самому участнику и владельцам пространства.
- [ ] Исключение исторического распределения задач по статусам из статистики за период.

**Перед реализацией:** отдельно утвердить методику расчёта показателей за период. Аналитические данные, требующие истории изменений, должны опираться на записи, которые сохраняются на предыдущих этапах.

**Результат:** участники получают общую статистику пространства, а владельцы и исполнители — предусмотренную индивидуальную статистику.

---

## Границы текущего плана

В план **не входят**: архив, корзина, комментарии, уведомления, повторяющиеся задачи, чек-листы, дублирование задач, неавторизованные гости, гостевые ссылки и индивидуальные разрешения на назначение задач другим людям.

**Примечание о порядке:** этапы сгруппированы по функциональным зависимостям. Инфраструктуру проверки прав, транзакционные ограничения и хранение необходимых данных следует добавлять вместе с соответствующими функциями, а не откладывать до последнего этапа.
