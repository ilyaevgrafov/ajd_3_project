# Функциональные требования

## 1. Назначение системы

Система предназначена для персонального и совместного управления задачами в независимых пространствах. В каждом пространстве собственные участники, статусы и теги. Пользователи могут работать с задачами в отдельном пространстве либо просматривать свои задачи сразу из нескольких пространств.

Этот документ описывает **планируемые возможности и бизнес-правила**, без порядка реализации. Последовательность разработки приведена в [roadmap.md](roadmap.md).

## 2. Терминология

| Термин | Значение |
| --- | --- |
| Пользователь | Человек с зарегистрированной учётной записью |
| Пространство | Независимая область управления задачами |
| Пользователь пространства | Пользователь, вступивший в пространство с ролью `GUEST`, `MEMBER` или `OWNER` |
| Гость (`GUEST`) | Пользователь пространства, имеющий доступ только к чтению |
| Участник (`MEMBER`) | Пользователь пространства с правом создавать задачи и работать с ними в пределах своих полномочий |
| Владелец пространства (`OWNER`) | Пользователь с административными правами внутри пространства |
| Создатель задачи | Пользователь, создавший задачу; его не следует путать с владельцем пространства |
| Исполнитель задачи | Назначенный пользователь с ролью `MEMBER` или `OWNER` |
| Свободная задача | Задача без исполнителя |
| Начальный статус | Крайний слева статус пространства; задача считается невыполненной |
| Конечный статус | Крайний справа статус пространства; задача считается выполненной |
| Промежуточный статус | Любой статус между начальным и конечным |
| Прямое назначение | Назначение исполнителя при создании своей задачи либо владельцем пространства |
| Самостоятельное назначение | Взятие пользователем с ролью `MEMBER` свободной задачи в работу |

## 3. Учётная запись и аутентификация

### 3.1. Регистрация и вход

- Регистрация с именем пользователя, отображаемым именем, электронной почтой и паролем.
- Уникальность имени пользователя и адреса электронной почты.
- Вход по паролю и выход из учётной записи.
- Доступ к пространствам только после аутентификации.

### 3.2. Электронная почта

- Подтверждение адреса электронной почты после регистрации.
- Повторный запрос подтверждения.
- Восстановление пароля по электронной почте с использованием одноразового проверочного кода.

### 3.3. Профиль и безопасность

- Изменение отображаемого имени и имени пользователя.
- Загрузка, замена и удаление аватара.
- Изменение пароля с подтверждением текущего пароля и использованием одноразового проверочного кода, отправленного на почту.
- Изменение электронной почты с вводом текущего пароля и подтверждением нового адреса кодом.
- Удаление учётной записи с вводом пароля и предупреждением о последствиях.
- При удалении учётной записи автоматически применяется логика выхода пользователя из всех пространств (раздел 5.5).

## 4. Пространства задач

### 4.1. Создание и поиск

- Любой аутентифицированный пользователь может создать пространство, указав **только название**.
- Создатель пространства получает роль `OWNER`.
- При создании автоматически появляются начальный и конечный статусы задач.
- Пользователь видит список пространств, в которых состоит, и может искать их по названию.

### 4.2. Управление пространством

Владельцы пространства могут:

- Изменять название пространства.
- Управлять приглашениями, составом и ролями пользователей.
- Управлять статусами и тегами задач.
- Удалять пространство.

Любой пользователь пространства может покинуть его; для владельца действуют специальные правила передачи владения.

### 4.3. Удаление пространства

- Владелец может удалить пространство после подтверждения.
- Вместе с пространством удаляются связанные задачи, их история, статусы, теги, приглашения и связи пользователей с пространством.

## 5. Роли, приглашения и жизненный цикл участия

### 5.1. Ролевая модель

**`GUEST` — гость:** только просмотр задач и всех доступных полей, пользователей, статусов, тегов, истории изменений и общей аналитики пространства. Не может создавать, изменять, удалять или выполнять задачи; гостя нельзя назначить исполнителем.

**`MEMBER` — участник:** может создавать задачи для себя или без исполнителя; редактировать и удалять свои задачи; изменять статус назначенной ему или свободной задачи; самостоятельно брать свободную задачу и возвращать её в свободные, если взял её сам. Не может назначать задачи другим людям. Может редактировать чужую задачу, если является её исполнителем и для задачи включено разрешение `assigneeCanEdit`.

**`OWNER` — владелец:** все возможности участника плюс полный контроль над задачами, исполнителями, статусами, тегами, пользователями, приглашениями, ролями и настройками пространства. Может назначить любую задачу любому `MEMBER` или `OWNER` данного пространства.

### 5.2. Матрица основных прав

| Операция | `GUEST` | `MEMBER` | `OWNER` |
| --- | :---: | :---: | :---: |
| Просматривать задачи, историю, статусы и теги | Да | Да | Да |
| Создавать задачи | Нет | Да | Да |
| Редактировать и удалять собственные задачи | Нет | Да | Да |
| Редактировать чужую задачу | Нет | При `assigneeCanEdit = true` и назначении исполнителем | Да |
| Удалять чужую задачу | Нет | Нет | Да |
| Создавать задачу без исполнителя / для себя | Нет | Да | Да |
| Назначать другого исполнителя | Нет | Нет | Да |
| Взять свободную задачу себе | Нет | Да | Да |
| Освободить самостоятельно взятую задачу | Нет | Да | Да |
| Изменять статус назначенной себе задачи | Нет | Да | Да |
| Изменять статус свободной задачи | Нет | Да | Да |
| Управлять статусами и тегами | Нет | Нет | Да |
| Приглашать и исключать пользователей, менять роли | Нет | Нет | Да |
| Просматривать общую аналитику | Да | Да | Да |
| Просматривать собственную индивидуальную аналитику | — | Да | Да |
| Просматривать индивидуальную аналитику других | Нет | Нет | Да |
| Удалять пространство | Нет | Нет | Да |

### 5.3. Приглашения

- Только владелец может пригласить **зарегистрированного пользователя** по его имени пользователя.
- При отправке приглашения владелец выбирает будущую роль: `GUEST`, `MEMBER` или `OWNER`. По умолчанию установлена роль `MEMBER`.
- Приглашаемый может принять или отклонить приглашение.
- Доступ предоставляется после принятия; владелец может отменить не принятое приглашение.

### 5.4. Изменение роли и исключение

- Владелец может изменить роль уже вступившего пользователя на `GUEST`, `MEMBER` или `OWNER`.
- После изменения роли немедленно применяются новые полномочия.
- При переводе исполнителя в `GUEST` его назначения снимаются; перед операцией показывается число затронутых задач.
- Созданные таким пользователем задачи сохраняются.
- Владелец может исключить любого участника пространства, кроме себя.
- После исключения пользователь утрачивает доступ, созданные им задачи сохраняются, а назначения исполнителем сбрасываются.

### 5.5. Выход из пространства и удаление учётной записи

**Добровольный выход:**

- Если после выхода остаётся хотя бы один `OWNER`, пространство сохраняется.
- Если выходит последний владелец и остаются `MEMBER`, он выбирает нового владельца среди них либо удаляет пространство.
- Если после выхода не остаётся ни одного `OWNER` или `MEMBER`, пространство удаляется автоматически.

**Удаление учётной записи:**

- Если после удаления учётной записи не остаётся владельцев, автоматически назначается новый `OWNER`: первый по времени вступления оставшийся `MEMBER`, а при отсутствии `MEMBER` — первый по времени вступления оставшийся `GUEST`.
- При равной дате вступления порядок определяется по идентификатору пользователя.
- Если после удаления учётной записи в пространстве не остаётся пользователей, пространство удаляется.

**Судьба задач при выходе, исключении или удалении аккаунта:**

- Задачи, созданные пользователем, сохраняются, пока существует пространство.
- Если пользователь был исполнителем задачи, задача становится свободной.
- Редактировать задачу после ухода создателя могут владельцы пространства, а назначенный исполнитель — только при наличии предусмотренного разрешения.
- История действий сохраняется; при удалении учётной записи не требуется сохранять публично доступные персональные данные удалённого пользователя.

## 6. Задачи

### 6.1. Поля задачи

| Поле | Назначение |
| --- | --- |
| Идентификатор | Уникальный идентификатор задачи |
| Пространство | Пространство, которому принадлежит задача; после создания не меняется |
| Создатель | Пользователь, создавший задачу |
| Исполнитель | Один `MEMBER`/`OWNER` данного пространства или отсутствие исполнителя |
| Название | Обязательное текстовое поле |
| Описание | Текстовое описание, может быть пустым |
| Дедлайн | Необязательный срок выполнения |
| Приоритет | `LOW`, `MEDIUM`, `HIGH`, `URGENT` |
| Статус | Один статус из набора статусов пространства |
| Теги | Ноль или несколько тегов пространства |
| Разрешение редактирования исполнителем | Признак `assigneeCanEdit`, по умолчанию выключен |
| Источник назначения | Прямое назначение, самостоятельное назначение или отсутствие назначения |
| Даты | Время создания и последнего изменения |

Приоритеты фиксированы для всей системы, а статусы и теги определяются каждым пространством отдельно.

### 6.2. Создание

- `MEMBER` может создать задачу **для себя** или **без исполнителя**.
- `OWNER` может создать задачу для себя, любого `MEMBER`/`OWNER` своего пространства или без исполнителя.
- Гости не могут создавать задачи.
- Название обязательно; описание, дедлайн, теги и исполнитель могут отсутствовать.
- При отсутствии выбранного статуса используется начальный статус пространства.
- При отсутствии выбранного приоритета используется `MEDIUM`.
- При создании можно настроить «**Разрешить исполнителю редактировать задачу**»; значение по умолчанию — выключено.

### 6.3. Редактирование

- Создатель задачи, пока обладает необходимыми правами участия в пространстве, может редактировать её содержание и удалять её.
- Владелец пространства может редактировать и удалять любую задачу.
- Исполнитель может менять название, описание, дедлайн, приоритет и теги при `assigneeCanEdit = true`, независимо от способа назначения.
- Исполнитель не получает только на основании этого разрешения права менять создателя, пространство, исполнителя или сам флаг разрешения; удалять задачу также нельзя.
- Поле `assigneeCanEdit` изменяют только создатель (если сохраняет полномочия) и владельцы пространства.
- Поле пространства после создания задачи не изменяется.
- Права на изменение статуса отдельно определены ниже.

### 6.4. Назначение исполнителя

**Прямое назначение:**

- Владелец пространства может назначать и изменять исполнителя любой задачи без дополнительных разрешений.
- Участник может назначить себя при создании собственной задачи; он не может назначить другого пользователя.
- Нельзя назначить гостя или пользователя, не состоящего в пространстве.
- Назначенный владельцем исполнитель не может самостоятельно отказаться от задачи.

**Самостоятельное назначение свободной задачи:**

- Любой `MEMBER` может назначить себе любую задачу без исполнителя, в том числе созданную другим человеком.
- Самостоятельно взявший чужую задачу `MEMBER` может изменять её статус и, при `assigneeCanEdit = true`, редактировать её содержание.
- Самостоятельно взявший задачу `MEMBER` может вернуть её в состояние без исполнителя.
- Создатель сохраняет свои права редактирования собственной задачи.
- Прямое переназначение владельцем отменяет возможность самостоятельно освободить задачу.
- Операция взятия задачи должна исключать одновременное назначение двум пользователям.

Для корректного применения правил система должна различать прямое и самостоятельное назначение, а также отсутствие исполнителя.

### 6.5. Статус и завершённость

- Статус задачи может изменить её создатель с действующими правами, назначенный исполнитель, любой участник при отсутствии исполнителя и любой владелец пространства.
- Гость не может изменять статус.
- Изменение статуса само по себе не меняет исполнителя.
- Задача считается выполненной **только** в конечном (самом правом) статусе; все остальные статусы соответствуют невыполненным задачам.

### 6.6. Удаление

- Удалять задачу может её создатель с действующими правами или владелец пространства.
- Удаление требует подтверждения.
- Удалённая задача не попадает в архив или корзину и не восстанавливается через интерфейс.

## 7. Статусы пространства

- У каждого пространства собственный упорядоченный набор минимум из двух статусов.
- Начальный статус всегда находится **слева**, конечный — **справа**.
- Начальный и конечный статусы можно **переименовывать**, но нельзя удалять или перемещать на промежуточные позиции.
- Владелец может создавать, переименовывать, перемещать и удалять промежуточные статусы.
- Порядок статусов задаёт порядок столбцов канбана.
- При удалении промежуточного статуса связанные задачи переводятся в начальный статус.
- Если удаляемому статусу соответствуют задачи, система перед подтверждением показывает **количество затронутых задач**.

## 8. Теги пространства

- У каждого пространства собственные теги.
- Владелец может создавать, переименовывать и удалять теги.
- Одна задача может иметь несколько тегов.
- При удалении тега он снимается со всех задач, но сами задачи сохраняются.
- Если тег используется, перед подтверждением отображается количество задач, которые его потеряют.

## 9. Представления, поиск и фильтрация

### 9.1. Представления отдельного пространства

- **Бэклог:** список задач пространства.
- **Канбан:** доска, где столбцы соответствуют упорядоченным статусам пространства.
- **Календарь:** отображение задач с учётом их дедлайнов.

Права на изменение задач одинаковы независимо от выбранного представления.

### 9.2. Поиск, сортировка и фильтры

- Поиск задач по названию и описанию.
- Сортировка задач по дедлайну и статусу.
- Фильтрация по исполнителю и тегам.
- Фильтрация по дедлайну: сегодня, текущая неделя, произвольный промежуток.
- Поиск пространств пользователя по названию.

### 9.3. Общие представления

Пользователь может видеть задачи из всех пространств, в которых он состоит:

- В общем бэклоге.
- В общем календаре.
- В общем канбане с двумя столбцами: **«Не выполнено»** и **«Выполнено»**.

В общем канбане задача попадает в «Выполнено» только при нахождении в конечном статусе **своего** пространства; в остальных случаях — в «Не выполнено».

Доступность и изменяемость задач сохраняются в соответствии с ролью пользователя в исходном пространстве.

## 10. История изменений задачи

- Для каждой задачи хранится история изменений её полей, за исключением принадлежности пространству, которая неизменна.
- Для каждой записи показываются **дата и время, автор и содержание изменения** (что было изменено).
- Историю задачи могут просматривать все пользователи соответствующего пространства, включая гостей.
- Просмотр истории не даёт права изменять задачу.
- При удалении аккаунта история не должна требовать существования активной учётной записи бывшего автора.

## 11. Аналитика пространства

### 11.1. Общие показатели

Всем пользователям пространства, включая `GUEST`, доступны:

- Общее количество задач пространства.
- Количество просроченных задач.
- Текущее распределение задач по статусам.

### 11.2. Индивидуальные показатели

Для каждого `MEMBER` и `OWNER` предусматриваются:

- Количество задач, назначенных пользователю.
- Количество просроченных задач пользователя.
- Текущее распределение назначенных пользователю задач по статусам.

Индивидуальные показатели доступны соответствующему пользователю и владельцам пространства.

### 11.3. Периоды

Для применимых количественных показателей предусматривается выбор периода: текущий день, текущая неделя, произвольный промежуток или всё время. Распределение задач по статусам показывает текущее состояние и не рассчитывается за исторический период.

Методика расчёта показателей за период утверждается до реализации аналитики.

## 12. Общие ограничения и инварианты

1. У существующего пространства должен быть минимум один владелец.
2. В пространстве всегда есть минимум два статуса: начальный и конечный.
3. Задача принадлежит ровно одному пространству, и её нельзя переносить между пространствами.
4. Статус и все теги задачи принадлежат тому же пространству, что и задача.
5. У задачи не более одного исполнителя; исполнитель не может быть гостем.
6. Гости могут только просматривать данные и не могут выполнять операции изменения.
7. `MEMBER` не может назначать исполнителем другого пользователя.
